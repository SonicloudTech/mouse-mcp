# 定位（逼近）算法设计 — umouse sdk-host

本文档是 `hardware_action.hpp` 中闭环定位算法的权威设计说明：演进历史、实测依据、
当前模型、跨设备/跨机器可用性边界、验证方法与已知限制。修改定位逻辑前先读本文。

## 1. 问题与链路

`umouse_mouse_action` 的 move/drag 需要把光标收敛到目标物理像素。命令链路是三层量化叠加：

```
SDK dx/dy (HID counts, ±127/帧)
  → 固件（≤2 counts 不执行、不上报 —— 实测确认的黑洞）
  → Windows 指针弹道（EPP 开启时增益随速度变化：慢 <1.0、快 ~2.2-2.5）
  → GetCursorPos 整数像素（亚像素被截断）
```

坐标 x/y 是桌面物理像素；显示器 DPI/缩放不影响本链路（代码中唯一 DPI 相关逻辑是
窗口观察的 per-monitor 感知）。

## 2. 演进历史

**v0（最初）**：单一标量增益，每个动作从 1.0 重学。实测设备真实增益 1.9~2.3（大帧），
导致每个动作首帧约 2 倍过冲（画图验收时的"甩墨"根因）；末尾 1-2 counts 修正帧落入
固件黑洞，闭环等满 5000ms 反馈预算 → `feedback_timeout`（141 段橡皮擦拭中出现 8 次）。

**v1（0.4.24，2026-10-19 上午）**，三项修复：
1. **增益跨动作持久化**：`PositioningMemory`（per deviceId）保存上动作学到的标量增益，
   夹在 [0.5,4.0]，闲置 60s 向 1.0 半衰减；
2. **残差 ≤4px 即停**（native 环/按压前/终检/TS 收据四处一致）；
3. **微帧兜底**：命令最小 3 counts；|cmdX|+|cmdY|≤8 的小帧反馈等待上限 300ms，
   无反馈即断环并如实报 `position_below_device_resolution`。
   实测：12/12 移动完成，中位 505ms（原 732ms），最大 1064ms（原 4788ms），零超时零停摆。

**v2（2026-10-19 下午，本文）**。挖掘 10-17 验收 + 当日验证共 26 个轨迹、1692 个定位帧，
确认了弹道曲线的存在与形状（见 §3），据此把标量增益升级为**幅度分桶的增益曲线**，
并解决跨机器/跨设备可用性：

1. **曲线模型**：增益 = 幅度的函数（11 桶 + 中点线性插值），替代单一标量；
2. **联合不动点规划**：双轴共用按矢量幅度查出的增益（弹道按矢量速度加速，
   实测对角帧同幅度增益更高：91-127 桶矢量 2.47 vs 单轴 ~1.9-2.2）；
3. **鲁棒在线学习**：方向一致才采纳、幅度区间 [0.125,10]、两级 EMA、离群丢弃；
4. **环境感知种子**：首次使用某设备时只读查询本机指针设置（`SPI_GETMOUSE` +
   `SPI_GETMOUSESPEED`），EPP 关 → 种子=平坦的档位乘数；EPP 开 → 种子=实测弹道形状×档位乘数；
   种子只是初值，学习永远优先（这是"换电脑也能用"的关键，见 §5）；
5. **宽钳制 [0.125,10]**：覆盖 Windows 灵敏度全部 20 档（1/32 ~ 10×），修复 v1 中
   [0.5,4.0] 在低/高档位机器上学习被卡住的问题；
6. **`precision:"high"` 档**：末段整形到 ≤1px（详见 §4.6）。

## 3. 实测依据（参考台架：EPP 开、档位 10/20=1:1、帧距 ~40ms）

挖掘脚本 `.tmpprobe/mine-gain.mjs`；数据：X 542 / Y 642 / 矢量 486 帧。

| 命令幅度 (counts) | 增益中位 px/count（X/Y） | 实际步长中位 |
|---|---|---|
| 3-4 | 0.67 / 0.50 | ~2px |
| 5-6 | 0.80 | ~4px |
| 7-8 | 1.00（过 1.0 点） | ~7px |
| 9-12 | 1.08 / 1.09 | ~12px |
| 13-16 | 1.15 | ~15px |
| 17-24 | 1.53 / 1.45 | ~32px |
| 25-32 | 1.97 / 1.93 | ~61px |
| 33-48 | 2.15 / 2.13 | ~85px |
| 49-64 | 2.25 | ~117px |
| 65-90 | 2.42 / 2.35 | ~183px |
| 91-127 | ~1.9-2.2（p90 2.5） | ~237px |

结论：X/Y 统计同曲线（放大来自 Windows 弹道，不是固件按轴缩放）；小帧增益 <1
意味着 3 counts 只动 ~2px——这是天然的细调刻度，`precision:"high"` 借此可到 1px 级。
已知噪声：9-12 与 91-127 桶有少量离群样本（疑似弹道速度历史依赖：大帧后紧接的小帧
被瞬时放大），由学习侧的离群丢弃吸收，不做显式建模。

默认种子曲线（`kBallisticSeedCurve`，即上表）：`{0.65,0.80,0.98,1.08,1.15,1.49,1.95,2.14,2.25,2.38,2.30}`。

## 4. 当前设计

### 4.1 增益曲线
11 个幅度桶（上限 4/6/8/12/16/24/32/48/64/90/127），桶间用中点线性插值
（避免规划在桶边界震荡）。曲线按**矢量幅度** `hypot(cmdX,cmdY)` 查询。

### 4.2 规划（每帧命令的求逆）
给定误差 (dx,dy)，联合不动点迭代 ≤4 次：`cmd = round(err*0.9/g)`、
`g = curveAt(|cmd|)`。0.9 是保守系数（宁可欠一点，闭环补）。之后：
- 误差 ≤ 容差的轴命令清零（不引入横轴扰动）；
- 需修正的轴命令至少 3 counts（固件量子，见 §4.7）；
- 全轴夹在 ±127。

### 4.3 学习（每帧落定后）
采纳条件：有位移、位移与命令点积 >0（方向一致）、观测增益在 [0.125,10]。
`观测增益 = |位移| / |命令|`，记入该帧幅度对应的桶：
- 距当前值 ≤ max(1.0, 1.5×当前值)：EMA 步长 0.5（快速采纳）；
- 更远（可能真实环境差异也可能污染）：EMA 步长 0.2（仍会走，只是慢）。
区间外的观测（如 >10）直接丢弃。v1 的"标量末帧增益被原样带入下个动作首帧"
造成的种子混乱（实测 0.8~2.67 乱跳）由此消除——记忆的是整条曲线。

### 4.4 记忆与衰减
`PositioningMemory` per deviceId（std::map 节点地址稳定，arbiter 保证同设备同时
只有一个动作在跑，取元素指针传入安全）。每次学习即写回。闲置 >60s：每桶向**种子**
半衰减（v1 向 1.0 衰减；v2 向种子衰减，因为种子编码了本机环境）。

### 4.5 环境感知种子（跨机器的关键）
首次为某设备建记忆时，插件**只读**查询（绝不写用户设置）：
- `SPI_GETMOUSE` → `{threshold1, threshold2, speed}`，`speed != 0` 判定加速度开启；
- `SPI_GETMOUSESPEED` → 档位 1..20，查文档乘数表（10 = 1:1，范围 1/32 ~ 10×）。

种子：EPP 关 → 全桶 = 档位乘数（平坦）；EPP 开 → `kBallisticSeedCurve × 乘数`。
轨迹事件 `action.position.envSeed` 记录判定与种子曲线。种子错得再离谱也只影响
首帧质量：闭环观测-迭代保证收敛（v1 时代种子乱跳仍 12/12 完成即是实证），
学习会把曲线改写成任何真实形状（包括平坦）。

### 4.6 `precision` 档（动作可选字段，默认 `"standard"`）
- standard：容差 4px 即停（v1 行为，速度优先）；
- high：容差 1px。残差进入 ≤4px 后继续用曲线反解的 3-5 counts 微帧修正
  （小帧增益 <1 → 3 counts ≈ 2px → 1px 级可达）。
  **防振荡**：连续 3 帧残差无改善即接受当前值停环（`action.position.stall_accepted`），
  落点仍受 ≤4px 终检约束——**high 档永远不会比 standard 更差，失败模式与 standard
  完全相同**；在最小步长过大（如平坦高增益设备）的机器上退化为 best-effort ≤4px，
  残差如实上报。
- 非法值 → `invalid_precision`（native 与 TS 合同同步校验）。

### 4.7 固件量子与微帧兜底（v1 保持不变）
最小命令 3 counts；`|cmdX|+|cmdY|≤8` 的小帧反馈等待上限 300ms，无位移即断环，
报 `position_below_device_resolution`（区分"设备做不到"与"卡死等预算"）。

## 5. 跨设备/跨机器可用性矩阵

| 变化项 | 影响 | 机制 |
|---|---|---|
| 换电脑（EPP 开、任意档位） | 首帧即准 | 环境感知种子 ×档位乘数 |
| 换电脑（EPP 关） | 首帧即准（平坦种子） | 同上；学习会把曲线压平 |
| 非默认档位（0.375× ~ 10×） | 可学 | 宽钳制 [0.125,10] 覆盖全 20 档 |
| 厂商驱动/自定义弹道曲线 | 首帧差、2-3 帧内收敛 | 种子失配由在线学习吸收 |
| 换 umouse 设备单元 | per-device 记忆重新种子化 | 同一固件家族 → 3-count 量子一致 |
| 换固件版本 | 需重验 §4.7 假设 | 量子与上报行为是固件属性 |
| 显示器 DPI/缩放/多屏 | 无影响 | 坐标即物理像素 |
| RDP / 触屏独占 / 安全桌面 | **不支持** | 光标通道被接管，合同外 |

冷启动验收口径：任何配置下 ≤3 帧进入 ≤4px、0 超时。跨机器矩阵验证脚本：
`.tmpprobe/curve-cal.mjs`（幅度扫描拟合曲线）+ `.tmpprobe/precision-probe.mjs`
（24 网格点），换机器各跑一次、曲线族归档 `.diagnostics` 即可复核。

## 6. 验证

- **native 合同**（`test/hardware_contract.cpp`，fake 设备）：
  `gain-memory`（曲线形 fixture ×1.4：冷启过冲 vs 记忆后首帧落点、桶记忆保留）、
  `precision-high`（1 帧收敛到 ≤1px）、`precision-stall`（高增益平坦设备上
  停滞接受 ≤4px 不振荡）、`seed-flat`（0.3 低增益"机器"可学到 0.3，验证宽钳制）、
  `seed-curve`（乘数表与种子函数纯断言）、既有 `tolerance-4`/`micro-stall`/
  `move-quantized` 等全部保持。
- **全量**：仓库根 `npm test`（267+ native adapter 用例 + TS 合同）。
- **台架**：部署后跑 12 步中距移动（标准档）应 ≤3 帧/步；高精度档网格探针
  残差中位 ≤1px、P95 ≤2px；轨迹中应见 `action.position.envSeed` 与
  `gainRestored`（曲线数组）。

## 7. 已知限制与固件诉求

- 软件可达地板 ~1px（GetCursorPos 整数化 + 小帧增益方差 ±0.3px）；
  0px 需固件侧绝对定位接口（HID digitizer 页）。
- 固件诉求（带 §3 数据）：① 执行并上报 1-2 counts（EPP 下 1 count ≈ 0.3-0.6px，
  配合重复发送可亚像素累积）；② 反馈携带实际执行计数 ACK；③ 绝对定位接口（终极）。
- 明确不做：临时关闭/修改用户指针设置（系统全局副作用，且关 EPP 后小帧量子
  反而变粗：3 counts = 3px）。
